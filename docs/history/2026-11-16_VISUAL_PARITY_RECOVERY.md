## 1. Задача

После публикации Draft PR #1 оставались четыре расхождения визуальной части
от оригинального production. Требовалось установить, это «только CSS» или
отсутствие DOM/функциональности, восстановить поведение из проверенных
production-артефактов, перепроверить сценарии, безопасность и сборку, обновить
PR — **без merge, без production-деплоя и без миграций**.

## 2. Диагноз: это отсутствующий DOM, а не только CSS

В ветке не было ни самих элементов, ни их правил — ни в одном файле:

| Расхождение | Что отсутствовало в ветке |
| --- | --- |
| `.footer-legal a` | навигация «Документы» в подвале (`/legal`, `/legal/privacy`) |
| `.form-privacy-note` (главная) | примечание о персональных данных под формой заявки |
| `.form-privacy-note` (аналитика) | примечание `.brief-privacy-note` |
| `.profile-actions .recovery-link` | ссылка «Подтвердить Telegram и сменить пароль» |

## 3. Метод проверки: рендеринг, а не сравнение исходников

Сравнение исходников не может доказать паритет: DOM мог быть утрачен вместе
с CSS. Поэтому собран стенд, который поднимает **оригинальный production-образ**
`kiruhak-app:materials-privacy-20261109` и **сборку ветки** рядом на
изолированной пустой PostgreSQL (`kstudio-parity-db`) и сравнивает SSR-HTML
страниц с нормализацией scope-id, имён keyframes, хешей ассетов и build id.

Инструменты входят в репозиторий: `ops/verify-visual-parity.sh`,
`ops/compare-ssr-html.py`. Продакшен-контейнер и продакшен-база стендом не
затрагиваются.

## 4. Найдено сверх четырёх расхождений

Рендеринг выявил четыре дополнительных разрыва, которые чтение исходников не
показывало:

1. `/login`, `/legal` и `/legal/privacy` рендерились **без** шапки и подвала —
   страницы не были обёрнуты в `<NuxtLayout>` (`app.vue` использует
   `<nuxt-page />` и полагается на явную обёртку в каждой странице).
2. Заголовок колонки подвала: «Ссылки» вместо production-«Связаться».
3. Публичный контакт Telegram: `@kiruhak11` вместо `@kiruhak11bot`.
4. Кнопки выхода (`UserProfile`, `HamburgerMenu`) — без `type="button"`,
   `disabled`, `aria-busy` и подписи «Завершаем…».

Плюс мелочи, влияющие на вывод и SEO: dark-токен `--box-shadow-color` на
странице восстановления, тексты ошибок входа через Telegram, route rules
`robots` для `/account/recovery`, `/legal`, `/legal/privacy`, reduced-motion
правила (корневой `&` давал мёртвое `:scope[data-v-x]` вместо
`[data-v-x]`), порядок CSS-правил `.form-privacy-note` / `.form-actions`.

## 7. Ограничения

* Мобильные размеры проверены статически: встроенный браузер имеет фиксированный
  viewport 1280×720 и не умеет его менять. Медиазапросы в скомпилированном CSS
  совпадают с production побайтово.
* Ссылка восстановления доступа требует авторизации — реальные учётные данные
  не вводились; наличие ссылки подтверждено по DOM и compiled-чанку.
* Эталон паритета — только скомпилированный артефакт
  `materials-privacy-20261109`: отрендерить «старый» образ с production-БД и
  окружением нельзя, поэтому сравнение шло на пустой изолированной БД.
* `initAuth` в ветке восстанавливает сессию из localStorage, в production эта
  функция пустая. Расхождение намеренное, в сторону более полного поведения;
  отмечено как условие к merge.
* В `master` опубликован старый (уже отозванный) токен Telegram-бота в
  документации. Ротация и вычистка — вне рамок этой задачи.
